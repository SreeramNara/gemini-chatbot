Secret Management Overview

Cloud Run does NOT recommend embedding secrets in:

environment variables in source code
container images
build pipelines

Instead, secrets should be managed via Google Secret Manager integration.

Secret Access Architecture

Cloud Run accesses secrets using:

IAM-bound service account
runtime injection (not build-time injection)

This means:

secrets are resolved at runtime
access is evaluated dynamically per request or startup
Access Control Model

To access a secret:

Cloud Run service account must have:
roles/secretmanager.secretAccessor

Important:

permissions are checked at runtime
revoking IAM immediately blocks future access
Injection Methods
1. Environment Variable Injection
Secret value injected into environment variable
Available at runtime in application process

Use when:

configuration values needed at startup
2. Mounted Volume Secret
Secret mounted as file inside container
Useful for:
certificates
keys
structured configs
Security Rules
Never bake secrets into container layers
Avoid logging secret values (Cloud Logging can capture them unintentionally)
Rotate secrets without redeploying containers (if properly referenced)
Runtime Behavior
Secrets are fetched using service account identity
If IAM is invalid:
container fails at startup OR
secret value is unavailable at runtime
Best Practices
Use separate secrets per environment (dev/staging/prod)
Restrict access per service account
Enable secret versioning for safe rotation
